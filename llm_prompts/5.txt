PART B — LLM result card
  (new file: asreview/webapp/src/ProjectComponents/ReviewComponents/
             LlmResultCard.js)
------------------------------------------------------------------------
A small MUI <Card> that takes props { project_id, record_id, llm } where `llm`
is the initial item["llm"] from the record fetch.

Behavior:
  - If `llm` is null: render nothing (return null).
  - Poll ProjectAPI.fetchLlmMeta with react-query, ONLY while the status is a
    non-terminal state ("queued" | "in_flight"): set refetchInterval to 4000,
    seed initialData with the `llm` prop. Terminal states
    ("ready" | "failed" | "missing_pdf") stop polling (refetchInterval false).
  - Render by status:
      queued / in_flight -> a small CircularProgress + "Analyzing full text…"
      ready              -> a check icon + a compact metadata line:
                            model, latency (created_at − dispatched_at, in s),
                            input/output tokens, dispatched time (local).
      failed             -> plain error text incl. last_error.
      missing_pdf        -> plain text "No PDF available for this record."
  - This card is INFORMATIONAL only. The actual pre-fill of the label/list
    controls already happened server-side (Phase 3) and flows through
    RecordCardLabeler's existing state initializers — do NOT re-implement
    pre-fill here, and do NOT auto-submit anything.

Mount <LlmResultCard project_id record_id llm={record.state ? record.llm : ...}/>
inside RecordCard.js near the top of the record's card stack (above the
labeler). Read RecordCard.js to see how it receives the record object and the
project_id, and pass record.llm through.

PART E — backend: the llm-meta GET endpoint used by PART A.1
  (asreview/webapp/_api/projects.py)
------------------------------------------------------------------------
Add a tiny read-only route (model it on api_get_record's decorators/user_id
handling, reuse _current_prompt_hash + get_llm_meta from Phase 3):

    @bp.route("/projects/<project_id>/record/<record_id>/llm", methods=["GET"])
    @login_required
    @project_authorization
    def api_get_record_llm(project, record_id):  # noqa: F401
        prompt_hash = _current_prompt_hash(project)
        with project.db as db:
            meta = db.get_llm_meta(int(record_id), prompt_hash)
        return jsonify(meta)   # null when never dispatched

Also add the two dedicated LLM-settings routes (JSON, NOT form-encoded — the
existing api_update_project_info can't carry the nested "llm" object). Reuse
_llm_settings and DEFAULT_LLM_SETTINGS from Phase 3:

    @bp.route("/projects/<project_id>/llm_settings", methods=["GET"])
    @login_required
    @project_authorization
    def api_get_llm_settings(project):  # noqa: F401
        return jsonify(_llm_settings(project))

    @bp.route("/projects/<project_id>/llm_settings", methods=["PUT"])
    @login_required
    @project_authorization
    def api_update_llm_settings(project):  # noqa: F401
        body = request.get_json(silent=True) or {}
        # merge onto current, coerce numeric fields, keep only known keys
        current = _llm_settings(project)
        merged = {**current, **{k: body[k] for k in DEFAULT_LLM_SETTINGS
                                if k in body}}
        merged["buffer_size"] = max(1, int(merged["buffer_size"]))
        merged["max_concurrent_llm"] = max(1, int(merged["max_concurrent_llm"]))
        merged["stale_timeout"] = max(1, int(merged["stale_timeout"]))
        merged["criteria_text"] = str(merged["criteria_text"])
        project.update_config(llm=merged)
        # NOTE: Phase 6 adds the auto-reprocess trigger to THIS route.
        return jsonify(_llm_settings(project))
