PROBLEMS AND FIXES (already applied — review them)
------------------------------------------------------------------------
1. HIGH — a failed patch after a poll is lost for good (D2).
   poll commits markChanges (new watermark, new configVersion) BEFORE it
   fetches /records for idsToPatch and the forms. If either fetch fails,
   the next poll asks `since` the NEW watermark, so the server never
   reports those changes again: the card keeps its old content, or the
   forms stay old, with no banner, until something else changes.
   FIX (useCollection.js, poll .catch): roll back to the values from
   before the poll, `watermark: since`, `configVersion:
   prevConfigVersion`, but commit only if something actually moved (no
   re-render every 15 s while offline). A re-reported change is harmless
   (same version → no patch), a lost patch is not.

2. HIGH — a failed Refresh hides cards and removes the banner.
   refresh commits reconcile (stale = false, rows dropped for ids that
   must be fetched) BEFORE /records. If that fetch fails: new or moved
   cards are missing (visibleRows skips ids without a row), changed cards
   show old content, and the banner is gone, so the user cannot retry.
   FIX (refresh .catch): commit `stale: true` and the old configVersion.
   The next reconcile fetches exactly what is still missing or old,
   because versions only rise through applyRowUpdates.

3. MEDIUM — a Refresh click while busy is dropped silently.
   `if (busy.current) return;` A poll with patches can take a while; a
   click in that window does nothing.
   FIX: a `wantRefresh` ref, like `wantMore`. One `finish()` helper now
   releases `busy` and then runs the queued Refresh first, else the
   queued loadMore. All three operations end with `.finally(finish)`.
   `refreshRef` mirrors `loadMoreRef`.

4. LOW — a counter that went backwards breaks Refresh.
   The server replies reset when `since > watermark`, i.e. the project's
   version counter went backwards (a results.db restored under an open
   tab). Then server versions are lower than the client's, and reconcile
   (`item version > versions[id]`) would keep outdated rows.
   FIX (collectionModel.js): emptyState gets `rewound: false`. A reset
   whose watermark is lower than state.watermark sets the sticky
   `rewound: true`. In useCollection the mount effect body moved into
   `startSnapshot()`; Refresh calls it instead of reconciling when
   `state.rewound`. The banner still appears first (D1: no jump without a
   click). New Jest test "marks a reset with a lower watermark as rewound
   (sticky)", plus `rewound` false in the existing reset test.
