USER GOAL (acceptance criterion for today)
  On the Collections page, a user selects "Relevant" + filter
  "Full text (Zotero): False" and sees every relevant article that has no
  PDF. Each time they upload a PDF to one of those articles (PDF button on
  the card), that article disappears from the list, so the list shrinks to
  zero as they work through it. An article that has a PDF must never stay
  in that list.

DIAGNOSIS (verified by reading the code — trust this)
  Backend: api_get_labeled in asreview/webapp/_api/projects.py (~line 722)
    builds pdf_ids = records whose record.attachment is a Zotero key, and
    "pdf=false" keeps records NOT in that set. That logic is correct for the
    cached data. Never-checked records (attachment None) count as "no PDF";
    7b's background sync and the per-card check resolve those. KEEP this
    semantics: never-checked records are shown as missing until a check
    proves otherwise (hiding them would hide genuinely missing PDFs).
  Frontend — the actual bug: the list never refreshes when a record gains
    a PDF.
    - asreview/webapp/src/ProjectComponents/HistoryComponents/
      LabeledRecord.js loads the list with
      useInfiniteQuery(["fetchLabeledRecord", {project_id, subset, filter}]).
    - asreview/webapp/src/ProjectComponents/ReviewComponents/RecordCard.js,
      component ZoteroFullTextButton:
        * after a successful upload or replace it calls
          invalidateAttachment(), which invalidates only
          "fetchRecordAttachment" and "fetchLlmMeta" — NOT
          "fetchLabeledRecord". So the uploaded card stays in the
          "no full text" list.
        * when the card scrolls into view it calls the attachment endpoint,
          which may DISCOVER a PDF that was added in Zotero directly. The
          button turns into "PDF available", but the list is not refreshed,
          so the record stays in the "no full text" list.

PART B — frontend: refresh the list when a record gains a PDF
------------------------------------------------------------------------
All changes in RecordCard.js, inside ZoteroFullTextButton. queryClient is
already available there (useQueryClient).

  1. In invalidateAttachment(), also invalidate the Collections list:
         queryClient.invalidateQueries(["fetchLabeledRecord", { project_id }]);
     react-query v3 matches query keys by prefix/partial object, so this
     refetches every subset/filter variant of the list (the same call is
     already used in RecordCardLabeler.js — grep it to confirm the form).
     Upload and replace both go through invalidateAttachment, so both are
     covered.

  2. A PDF discovered by the on-screen check must also refresh the list.
     Add, after the useQuery for fetchRecordAttachment:

         // The list row was loaded without a PDF, but the live check found
         // one: refresh the Collections list so a "no full text" filter
         // drops this record.
         const listHadPdf = /^[A-Z0-9]{8}$/.test(record?.attachment ?? "");
         React.useEffect(() => {
           if (data?.available && !listHadPdf) {
             queryClient.invalidateQueries([
               "fetchLabeledRecord",
               { project_id },
             ]);
           }
         }, [data?.available, listHadPdf, project_id, queryClient]);

     (The regex mirrors zotero.ZOTERO_KEY_RE on the backend.) This cannot
     loop: after the refetch the row carries the key, so listHadPdf becomes
     true and the effect does nothing.

  Do not change the attachment query's options (staleTime 5 min,
  triggerOnce, etc.) — that 5-minute behaviour matches the backend's
  on-screen re-check window.
