WHY
  Every /labeled row embeds the full tags_form, the full lists_form and a
  user summary, so one 50-row page carries 50 copies of both forms. Forms
  are a single current definition (tags are stored by option id), so
  sending them once per response is pure de-duplication.
  This task also cuts api_get_labeled into helpers, because Part 4 adds
  three endpoints (labeled/ids, labeled/changes, records) that must filter,
  order and build rows EXACTLY like /labeled. Copies would drift.
  Finally, the two edit routes the Collection uses (PUT record, PUT note)
  return the updated row in the same shape, so the client can patch one
  card instead of reloading the list (D13).

DESIGN (decided — follow it)
  New /labeled response:
      {
        "count": <len(result)>,
        "next_cursor": <str|None>,
        "result": [rows],
        "forms": {"tags_form": [...], "lists_form": [...]|None},
        "users": {<user_id>: summary, ...}       # {} without AUTHENTICATION
      }
  Row = asdict(record) + "state" (all results columns incl. "user_id",
  "lists"; missing values → None). NO "tags_form", "lists_form" or
  "state.user".

  Helpers (module-level functions in projects.py, placed right before
  api_get_labeled, numpy-style docstrings like the neighbours):

  1. _parse_labeled_query(project) -> dict
     Moves the parameter parsing out of api_get_labeled unchanged:
     subset, filters, latest_first, parsed_filters, label, priors,
     has_note, include_users, exclude_users, tags_form (read_tags_data),
     tag_filters, invalid_filter, filter_pdf, filter_abstract, post_scan,
     filter_sig. Return them as a dict with exactly these keys:
       "subset", "filters", "latest_first", "label", "priors", "has_note",
       "include_users", "exclude_users", "tags_form", "tag_filters",
       "invalid_filter", "filter_pdf", "filter_abstract", "post_scan",
       "filter_sig"
     It does NOT read per_page or cursor (those belong to the route).

  2. _iter_labeled_matches(db, q, cursor=None, batch_size=500)
     A generator. It yields (state, key) for every record matching q, in
     display order, starting after `cursor` (a DECODED cursor tuple or
     None). `state` is the pd.Series row of the page DataFrame (tags
     parsed). key = (None if pd.isna(time) else float(time),
     int(record_id)), which is the same tuple _encode_cursor takes.
     It contains the pdf_ids / abstract_ids computation, `passes()` and
     the batch loop exactly as today. It stops when a batch is empty or
     shorter than batch_size. The caller must consume it inside the
     `with project.db as db:` block.

  3. _users_map(project) -> dict
     The current users block moved out unchanged. Returns {} when
     AUTHENTICATION is off.

  4. _build_rows(db, project, states) -> list[dict]
     states: an iterable of pd.Series results/unlabeled rows.
         ids = [int(s["record_id"]) for s in states]   (return [] if empty)
         records = db.input.get_records(ids)
         lists_by_record = db.get_lists_for_records(ids)
         for state, record in zip(states, records):
             record_d = asdict(record)
             state_d = {k: (None if _is_missing_scalar(v) else v)
                        for k, v in state.to_dict().items()}
             state_d["lists"] = lists_by_record.get(int(state["record_id"]), [])
             record_d["state"] = state_d
     (`project` is unused for now. Keep the parameter: Part 3 adds the
     record version here and Part 4 reuses the function.) Materialize
     `states` into a list first, because it is iterated twice.

  5. _collection_forms(project, tags_form) -> dict
         {"tags_form": tags_form, "lists_form": read_lists_data(project)}

  api_get_labeled becomes:
      per_page / cursor_param from request.args (as today)
      q = _parse_labeled_query(project)
      decode the cursor with q["filter_sig"] (400 on ValueError, as today)
      users = _users_map(project)
      with project.db as db:
          batch_size = (per_page + 1) if not q["post_scan"] \
                       else max(per_page + 1, 500)
          matched, has_next = [], False
          for state, key in _iter_labeled_matches(db, q, cursor, batch_size):
              if len(matched) == per_page:
                  has_next = True
                  break
              matched.append((state, key))
          next_cursor = (_encode_cursor(*matched[-1][1], q["filter_sig"])
                         if has_next and matched else None)
          result = _build_rows(db, project, [s for s, _ in matched])
      return jsonify({count, next_cursor, result,
                      forms: _collection_forms(project, q["tags_form"]),
                      users: users})
