WHY
  Since 10e, every INSERT / UPDATE / DELETE on tag_groups, tag_options
  and list_containers fires trg_ct_<table>_* (_CONFIG_CHANGE_SQL: bumps
  project_state.version and sets config_version). The form-editor routes
  in projects.py write every row on every save, changed or not:
  - update_tag_group: one UPDATE of the group + one upsert per option
    (ON CONFLICT DO UPDATE without a WHERE, so it always writes);
  - update_list: one UPDATE of the container.
  So saving a tag group without changes bumps config_version 1 + (number
  of options) times, and the clients of 10h/10i reload the forms for
  nothing. Same principle as 10e2: write a row only when it changes.
  Rare admin traffic, so this is about correctness of config_version,
  not speed.

FACTS (verified — trust these)
  - asreview/webapp/_api/projects.py:
    - update_tag_group (PUT /projects/<id>/tags/<group_id>):
      1. UPDATE tag_groups SET export_name, label_name,
         required_for_relevant, required_for_irrelevant, all_required,
         single, input_helper_text, sorted_at WHERE group_id=?
         and `if result.rowcount == 0: return 404`.
      2. For each value with an "id": INSERT INTO tag_options … ON
         CONFLICT(option_id) DO UPDATE SET export_name, label_name,
         free_text_enabled, free_text_required, sorted_at (no WHERE).
         For a value without an id: plain INSERT with uuid7().
      3. Deletes options not in the payload (IntegrityError ignored:
         the FK from tags protects options in use). Keep this.
      4. db._conn.commit().
      group_sorted_at / option sorted_at fall back to time.time() when
      the payload has none.
    - update_list (PUT /projects/<id>/lists/<list_id>): UPDATE
      list_containers SET name, required_for_relevant, description,
      sorted_at WHERE list_id=?, commit, `if result.rowcount == 0: 404`.
      sorted_at falls back to time.time().
    - create_tag_group / create_list insert new rows: a real change,
      leave them alone. delete_* routes: leave them alone.
  - IMPORTANT: once the UPDATE has a "changed" WHERE, rowcount is 0 for
    an unchanged save too, so rowcount can no longer mean "not found".
    The existence check must become a separate
    SELECT 1 FROM <table> WHERE <id> = ? before the write.
  - Client (SetupComponents/TagCard.js, ListCard.js) sends sorted_at for
    the group, the options and the list, keeping the stored value unless
    the user edits. The time.time() fallback only hits payloads without
    sorted_at (API callers, tests).
  - asreview/webapp/tests/test_api/test_projects.py::test_lists_crud
    covers create / read / update of lists. No existing test PUTs a tag

CHANGE (asreview/webapp/_api/projects.py: update_tag_group, update_list)
------------------------------------------------------------------------
  1. Existence: SELECT 1 … WHERE group_id = ? / list_id = ? first; 404
     when missing (same message as now). Then drop the rowcount check.
  2. sorted_at fallback: when the payload has no sorted_at, use the
     STORED value for an existing group / option / list (read it in the
     same SELECT); time.time() only for a new option.
  3. UPDATE tag_groups … WHERE group_id = ? AND (<col> IS NOT ? OR …)
     over all eight SET columns. Same for list_containers (four columns).
     Use IS NOT so NULLs compare correctly (description can be NULL).
     input_helper_text: read_tags_data returns NULL as "", so write
     `updated_tag_group.get("input_helper_text") or ""` and compare with
     COALESCE(input_helper_text, '') IS NOT ? — otherwise a group stored
     with NULL (older projects) bumps once on an unchanged save.
     list description is already written as `... or None`; GET returns
     NULL as "" and the PUT turns "" back into None, so plain IS NOT works.
  4. tag_options upsert: add
       WHERE tag_options.export_name IS NOT excluded.export_name
          OR tag_options.label_name IS NOT excluded.label_name
          OR tag_options.free_text_enabled IS NOT excluded.free_text_enabled
          OR tag_options.free_text_required IS NOT excluded.free_text_required
          OR tag_options.sorted_at IS NOT excluded.sorted_at
     to the DO UPDATE.
  5. Keep the option-removal loop and the responses as they are.
  6. Short comment at each WHERE: unchanged rows are not written, so the
     config triggers do not bump config_version (Spec 0001).

  Do not change database.py, the triggers, the create / delete routes,
  read_tags_data, or the client.
