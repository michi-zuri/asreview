
PROJECT
  ASReview LAB v3.0.6 fork (repo: michi-zuri/asreview, branch: mama).
  Flask backend (Python) + React frontend + per-project SQLite databases.
  We are adding LLM-assisted full-text screening: Claude pre-fills the
  screening form (label/tag groups + lists) for each PDF, and a HUMAN
  reviewer always makes the final decision. The LLM never decides
  autonomously — it only pre-fills a form that a human confirms or edits.

FACTS ABOUT THIS CODEBASE (verified — trust these over your assumptions)
  - The Zotero integration supports GROUP libraries ONLY. Config lives in a
    per-project zotero.json read by get_zotero_config(); it exposes
    group_id, group_slug, api_key, recheck_interval. There is NO "user vs
    group" library-type setting. Do not invent one.
  - A record's Zotero ITEM key is record.original_id.
    A record's ATTACHMENT is record.attachment, which holds EITHER a Zotero
    attachment key OR an ISO-8601 timestamp of the last failed lookup.
    Use zotero.is_attachment_key(value) to tell them apart.
  - "Prior irrelevant" means record.included == 0 (Record.included is 0, 1,
    or None). Screening decisions also exist in the results table
    (results.label), but the dispatch filter uses record.included == 0.
  - Saved tags in ASReview are keyed by NUMERIC id, not by export name
    (see _record_tags_invalid / _tag_is_checked in projects.py). The LLM is
    asked to return `export` names, so a mapping export->id is required
    before pre-filling. (Relevant to later tasks, not necessarily this one.)
  - The label schema the LLM must fill is the BINDING CONTRACT and is built
    from the DB tables (tag_groups/tag_options via read_tags_data, and
    list_containers via read_lists_data). A separate human-facing free-text
    block is only additional context, never the contract.
  - case_identifiers and issues are LISTS: their items live in the `lists`
    table; their shape/constraints are defined in `list_containers`.
  - Background work runs in a STANDALONE process (a socket queue-manager),
    not asyncio inside Flask. The LLM worker will be a standalone process.
  - PDFs are sent to Claude as base64 `document` content blocks (NOT the
    Files API). Model string is exactly: claude-opus-4-8
  - This fork targets MULTI-USER server installs (AUTHENTICATION=True).
