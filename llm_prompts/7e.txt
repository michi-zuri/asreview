    llm_dispatch row to status 'missing_pdf'

  - That row then sits there forever: top_up_dispatch only inserts records

  - Uploading/replacing a PDF through ASReview (api_upload_pdf,
    api_replace_record_pdf) already re-queues the record with

  - Two components discover PDFs that were added in Zotero directly:
      * the on-screen check: GET .../record/<rid>/attachment →
        projects.py :: api_get_record_attachment
      * the background sync thread running inside the llm-worker
        service: asreview/webapp/_api/zotero_sync.py ::
        sync_db_attachments
    Neither touches llm_dispatch today, so the record stays 'missing_pdf'.

PART A — DAO (database.py, next to mark_dispatch_missing_pdf)
------------------------------------------------------------------------
    def delete_missing_pdf_dispatch(self, record_id):
        """Delete a record's llm_dispatch row if its status is 'missing_pdf'.

        Used when a PDF has been found for the record. The record is not
        re-queued here; top_up_dispatch picks it up again in ranking order.
        Rows with any other status are left untouched.

        Returns
        -------
        bool
            True when a row was deleted.
        """
        con = self._conn
        cur = con.cursor()
        cur.execute(
            "DELETE FROM llm_dispatch "
            "WHERE record_id = ? AND status = 'missing_pdf'",
            (int(record_id),),
        )
        con.commit()
        return cur.rowcount > 0

    def get_missing_pdf_dispatch_ids(self):
        """Return record_ids whose llm_dispatch row is 'missing_pdf'."""
        cur = self._conn.cursor()
        return [
            r[0]
            for r in cur.execute(
                "SELECT record_id FROM llm_dispatch "
                "WHERE status = 'missing_pdf' ORDER BY record_id"
            )
        ]
