GOAL
  The per-project Anthropic API key (config["llm"]["api_key"], set in the
  project's LLM settings card) is the HARD SWITCH for the whole LLM
  feature. Without a key:
    - no record is ever inserted or re-queued into llm_dispatch,
    - the reviewer gets records in plain ASReview order (no LLM buffer),
    - no LLM pre-fill is applied,
    - the LLM info box (LlmResultCard) is not shown in the frontend.
  With a key, everything behaves exactly as today.
  Existing llm_dispatch / llm_results rows are NOT deleted when the key is
  removed; they are just ignored, and used again if a key is added back.

FACTS (verified by reading the code — trust these)
  - asreview/webapp/_api/projects.py: _llm_settings(project) merges
    DEFAULT_LLM_SETTINGS (api_key "") with project.config["llm"].
  - Every write into llm_dispatch from the webapp happens in projects.py,
    at exactly these six call sites (grep `top_up_dispatch|force_requeue|
    requeue_for_prompt_change` to confirm, nothing else calls them outside

PART A — one helper (projects.py, right below _llm_settings)
------------------------------------------------------------------------
    def _llm_enabled(project):
        """Whether LLM screening is enabled for the project.

        The project's Anthropic API key is the hard switch: without a
        non-blank key nothing is queued for the LLM and no LLM data is
        served to the frontend.
        """
        return bool(str(_llm_settings(project).get("api_key") or "").strip())

PART B — gate every queue write and the LLM data in projects.py
------------------------------------------------------------------------
  api_get_record:
    llm_on = _llm_enabled(project) at the top (next to `settings`).
    When llm_on is False:
      - do NOT call top_up_dispatch,
      - do NOT call checkout_oldest_dispatched (go straight from
        get_pending / reassign_stale to query_top_ranked) — otherwise
        leftover dispatch rows from a removed key would still dictate the
        order,
      - do NOT read llm_meta / payload, do NOT run the
        requeue_for_prompt_change block, do NOT pre-fill,
      - set item["llm"] = None,
      - skip the "llm buffer-miss" log line.
    Do not compute _current_prompt_hash when llm_on is False (it is only
    needed for LLM work). Keep the llm_on=True path byte-for-byte the same
    behaviour as today; restructure only as much as the gate requires.

  api_upload_pdf and api_replace_record_pdf:
    call db.force_requeue(...) (and compute prompt_hash) only if
    _llm_enabled(project). Storing the attachment key — and, in replace,
    db.delete_llm_results(record_id) — still always happens.
    The in_flight guard (get_llm_meta ... "in_flight" → 409) in replace and
    delete may stay as is (with no key there are no in_flight rows).

  api_reprocess_record:
    if not _llm_enabled(project):
        return jsonify({"message": "LLM screening is not configured"}), 409
    before touching the database.

  api_get_record_llm:
    if not _llm_enabled(project): return jsonify(None)
    (so a card that is still mounted stops showing LLM state).

  api_apply_llm:
    if not _llm_enabled(project):
        return jsonify({"message": "LLM screening is not configured"}), 409

  api_update_llm_settings:
    only run the old_hash/new_hash comparison + requeue_for_prompt_change
    when _llm_enabled(project) is True AFTER project.update_config(...).
    (Adding a key later does not need a requeue: the next get_record
    top-up fills the buffer.)

  llm_worker.run_worker_once:
    replace the `if not api_key:` check with
    `if not _llm_enabled(project):` (import it next to the existing local
    import of _llm_settings), so a whitespace-only key counts as "no key"
    in both places. Keep the warning log. Nothing else in the worker.
