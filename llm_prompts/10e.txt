DESIGN (decided — follow it)
  database.py, new method placed after _set_results_changes_triggers:

    def _ensure_change_tracking_triggers(self):
        """(Re)create the Spec 0001 change-tracking triggers.

        Runs on every read-write open: SQLite drops a table's triggers
        with the table, and some ``_fix_*`` functions rebuild tables.
        """

  Build the SQL with two small module-level helpers so that the bodies
  are written once:

    _ATTACHMENT_KEY_GLOB = "'" + "[A-Z0-9]" * 8 + "'"

    def _record_change_sql(rid, source):
        # rid is "NEW.record_id" or "OLD.record_id"
        return f"""
            UPDATE project_state SET version = version + 1;
            UPDATE record_versions
               SET version = (SELECT version FROM project_state)
             WHERE project_id = (SELECT project_id FROM project_state)
               AND record_id = {rid};
            INSERT INTO record_versions (project_id, record_id, version)
            SELECT project_id, {rid}, version FROM project_state
             WHERE NOT EXISTS (
                 SELECT 1 FROM record_versions
                  WHERE project_id = (SELECT project_id FROM project_state)
                    AND record_id = {rid});
            INSERT INTO change_log
                (project_id, version, record_id, source, changed_at)
            SELECT project_id, version, {rid}, '{source}',
                   (julianday('now') - 2440587.5) * 86400.0
              FROM project_state;"""

    _CONFIG_CHANGE_SQL = """
            UPDATE project_state
               SET version = version + 1, config_version = version + 1;"""
    (In an UPDATE every right-hand side sees the OLD row, so
    config_version becomes the NEW version. A test checks this.)

  Triggers (all `CREATE TRIGGER IF NOT EXISTS`, `FOR EACH ROW`, names
  prefixed trg_ct_):
    results:
      trg_ct_results_insert  AFTER INSERT ON results       → NEW, 'results'
      trg_ct_results_delete  AFTER DELETE ON results       → OLD, 'results'
      trg_ct_results_update  AFTER UPDATE OF label, time, note, user_id,
                             assigned_at ON results
                             WHEN OLD.label IS NOT NEW.label
                               OR OLD.time IS NOT NEW.time
                               OR OLD.note IS NOT NEW.note
                               OR OLD.user_id IS NOT NEW.user_id
                               OR OLD.assigned_at IS NOT NEW.assigned_at
                                                           → NEW, 'results'
      (NOT last_active, D10. The WHEN clause skips no-op writes. That is
      a planner refinement, flagged in the spec notes.)
    tags:  trg_ct_tags_insert (NEW), trg_ct_tags_update (NEW),
           trg_ct_tags_delete (OLD), source 'tags'
    lists: trg_ct_lists_insert (NEW), trg_ct_lists_update (NEW),
           trg_ct_lists_delete (OLD), source 'lists'
    record: trg_ct_record_attachment
            AFTER UPDATE OF attachment ON <record_table_name>
            WHEN OLD.attachment IS NOT NEW.attachment
             AND (COALESCE(OLD.attachment GLOB {K}, 0)
                  OR COALESCE(NEW.attachment GLOB {K}, 0))
                                                → NEW, 'attachment'
      (K = _ATTACHMENT_KEY_GLOB. Only changes that make a full text
      appear or disappear are tracked. Rewriting the failed-lookup
      timestamp is not. That is a planner refinement, flagged in the spec
      notes. If the user rejects it, drop the second AND line.)
    config: trg_ct_<table>_insert/_update/_delete for tag_groups,
            tag_options, list_containers → _CONFIG_CHANGE_SQL.
